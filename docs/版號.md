# 版號規則

2026-10-23 使用者定。上傳流程在 `CLAUDE.md`「改完之後」，執行的是 `tests/release.js`。

## 格式

`v主.次.修`，遊戲裡顯示時後面接上傳的日期時間，例如 `v0.1.0（2026-10-23 14:00）`（標題、設定頁、大廳、遊玩紀錄）。

## 哪一段要加

| 段 | 什麼時候加 | 例子 |
|---|---|---|
| 主 | 0 = 原型期。第一個完整版才變 1，**只有使用者說要的時候改** | v1.0.0 |
| 次 | 規則或內容有變：新的武器、晶片、敵人、機制，玩法改動，存檔格式改變。加「次」時「修」歸零 | v0.1.3 → v0.2.0 |
| 修 | 規則不變：修錯誤、調數值、美術、文字、效能 | v0.2.0 → v0.2.1 |

- **只有上傳才加**，平常的提交不加；還沒上傳的改動記在 `docs/版本紀錄.md` 的「（下一版）」那一行。
- 一次上傳裡只要有一項「次」的改動就加「次」；全部都是「修」的改動才加「修」。

## 怎麼加（在 `tests/` 跑）

| 指令 | 結果 |
|---|---|
| `node release.js` | 只檢查，不改版號（平常應該全綠） |
| `node release.js --patch --push` | 修 +1，全部檢查通過才提交並上傳 |
| `node release.js --minor --push` | 次 +1、修歸零，全部檢查通過才提交並上傳 |
| `node release.js 1.0.0 --push` | 直接指定（改「主」、或從舊版號換過來） |

- 換版號會一起改：`js/core/config.js` 的 `VERSION`、`index.html` 每個檔案網址的 `?v=`（瀏覽器一定重抓新檔）、`README.md` 的目前版本、版本紀錄「（下一版）」改成版號。
- 會擋下：版號不是三段數字、上傳卻沒換版號、目前還是舊格式時用 `--patch`／`--minor`。

## 多人

兩邊版號完全相同才能連線（`js/system/net.js`），版號只比相不相同、不比大小。換版後已經開著遊戲的人要重新整理。

## 舊版號

`mp-` 開頭的是 2026-10-23 以前的版號（多人版原型 2.x，沒有固定規則），留在版本紀錄裡不改。之後從 **v0.1.0** 開始（使用者 10-23 定）。
