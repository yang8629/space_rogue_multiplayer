## mp-2.17.0：組件升級

取代用量成長（照玩法擊殺累積、自動升級）。原因：擊殺本來就會發生，玩家沒有選擇；改成玩家自己決定升級給哪個晶片，隨時能在身上調整。

- 玩法晶片的等級 = 1 ＋ 插在它上面的組件數（`CFG.LV_PER_COMP`），最多 Lv3（進化）；`compileChain` 算好放在 `info[i].lv`，晶片 id 不帶等級（`base~插座`）。畫面用 `slotLv`、`lvName`、`lvShort`。
- 任何組件都算，包括放錯的（吸引插鏡像、超頻／收束插晶片）：標 `lvOnly`（只升級、沒有效果），照樣吃電，編輯器不擋、插座變淡。超過插座數、沒電的不算。
- 拿掉：`grow.need`、`checkGrowth`、成長條、`CFG.COOP_GROW`、奇異點「成長 ×2」「不會成長」、沙盒 Lv 按鈕、拖同一個晶片升級。
- 玩法擊殺留著（`tagPlay`／`payPlayTags`、`Game.playKills`，次數），紀錄畫面顯示；之後稀有晶片的狂熱、結晶、收割用它。
- 奇異點好結果機率改照插座數（`bhGood`）。三選一／商店晶片卡照插座數換框色（1 灰、2 藍、3 紫）。
- 模擬：隨機配裝不再抽 Lv2（等級來自插在晶片上的組件）；模擬電腦（`tests/bot/pick.js`）先把組件插在還沒進化的玩法晶片上，再插武器。
- 檢查：`node release.js` 測試、機制檢查 143 項全過（新項目「組件升級」「玩法擊殺」，弄壞機制時確認會失敗）。截圖：`art_lab/screenshots/電路編輯器_組件升級.png`、`三選一_插座框色.png`。
- 還沒做：整局模擬看通關率（前期武器插座 0 個，組件只能插晶片，升級可能偏快）；晶片模擬表、路線價值表的基準都會變，要使用者決定重跑哪些。

## 怎麼測（瀏覽器）

- 起本機伺服器：在專案上一層 `python3 -m http.server 8765 --bind 127.0.0.1`，開 `http://127.0.0.1:8765/<資料夾>/index.html`；console 跑 `MechCheck.runAll()`。
