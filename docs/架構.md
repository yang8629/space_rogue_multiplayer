# 架構

> 改程式前讀對應的段落。新增、拆分、搬移檔案，或改了某個檔案負責的事，同一個提交裡改這份。程式碼規則在 `CLAUDE.md`。

## 為什麼這樣分

網頁版是原型，內容和平衡做完後移植到 Godot（見 `設計方向.md`）。所以：

- **邏輯和畫面分開**：遊戲邏輯只改狀態、發事件；畫面只讀狀態、聽事件。移植時只重寫畫面層。
- **資料是純表**：數值和定義放 `js/data/`，移植時轉成 Godot 的 Resource／JSON。
- **事件取代直接呼叫**：`Events.emit` 對應 Godot 的 signal。
- **效能**：畫面、每幀的程式不重複線性搜尋、不重算；改完量頁面（超過 100 ms 要修）。上限、門檻照實測定，量的結果寫在設定旁邊。

## 分層

```
js/core/    共用、不碰遊戲狀態：設定 CFG、小工具、事件、空間格子類別、子彈格式、傷害歸屬、主迴圈
js/data/    資料表：數值、定義、說明文字（武器、晶片、零件、飛船、敵人、章節、詞綴、事件、航圖產生）
js/game/    遊戲邏輯：一局的流程、戰鬥、實體、敵人 AI、武器玩法、晶片效果、電路執行、場地、地圖物件、基地、靶場
js/system/  跟外界接：存檔、輸入、音效、設定、多人連線
js/ui/      畫面：WebGL 世界（gl/）、2D 畫布的 HUD、DOM 介面（選單、面板、編輯器、多人大廳）
```

| 層 | 可以用 | 不可以 |
|---|---|---|
| core | 只有自己（`main.js` 例外：它負責接起所有東西） | 讀寫 `Game` 或任何遊戲狀態 |
| data | core；`Save`（進度的讀寫）；表裡「算」的函式（見下面「程式風格」）在遊戲中才執行，可以讀遊戲狀態 | 改遊戲狀態、生子彈、扣血、呼叫特效；畫面排版 |
| game | data、core、`Events`、`Net`（多人同步）、`Input`、`Save`；`effects.js` 的特效函式（都是發事件） | DOM、`GLR`／`GL*`、`Screen`、`FX`、`SFX`（要表現就 `Events.emit`） |
| system | data、core、game | 畫面（要畫面做事就發事件，例：`net.js` 發 `netView`，`ui/lobby.js` 畫） |
| ui | 全部都能讀；改遊戲只能呼叫 `Game`／`Hub`／`Range` 的方法（按鈕 → `Game.buy(i)`、`Range.setSpawn`、`Hub.setDriving`） | 直接改遊戲欄位；每幀重複線性搜尋 |

載入順序只寫在 `index.html`。所有檔案共用同一個全域範圍，function 宣告只在自己的檔案內提前：載入時就執行的程式碼不能呼叫後面檔案的函式。

## 程式風格

規則照「換到 Godot 也能照用」寫；只有網頁版才有的寫法標「網頁版」。命名、註解、改完要做的事在 `CLAUDE.md`。

### 每一層放什麼

| 層 | 放 | 不放 |
|---|---|---|
| data | 數值、名稱、說明文字（由數字產生）、每樣東西的**代表色**（武器、飛船、晶片種類、事件、航圖節點的主色，跟名字一樣是身分）、「算」的函式 | HTML 排版（`<div>`、`class`、`style`、`<span>`、`<img>`）；說明文字只能用 `<b>` 強調。特效、狀態、HUD 的顏色。「做」的函式 |
| core | 跟遊戲狀態無關的工具：設定、數學、事件、格子類別、子彈格式、傷害歸屬 | 讀寫 `Game` |
| game | 狀態和行為：一局的流程、每幀更新、武器玩法、晶片效果、敵人 AI | 畫面（要表現就 `Events.emit` 或 `effects.js`） |
| system | 跟外界接：存檔（只有 `save.js` 碰 `localStorage`）、輸入、音效、設定、連線 | 組畫面、叫畫面重畫 |
| ui | 讀狀態畫出來：排版、顏色、文字的樣子、HUD 小條（例：`WEAPON_HUD`） | 改遊戲欄位（要改就呼叫方法） |

### 表裡的函式：只能「算」，不能「做」

- **算**：吃輸入、回傳結果，可以讀遊戲狀態。例：`CHIPS[id].apply(list)` 改子彈清單、升級的 `apply(p)` 改武器參數、`desc: v => …` 產生說明。→ 可以留在 data。
- **做**：改遊戲狀態、生子彈、扣血、呼叫特效。例：武器的右鍵、晶片放出的產物、砲塔出招。→ 放 game 的類別或表：`WEAPON_PLAY`（`weapon_play.js`）、`LINE_FX`（`pipeline.js`）、`TURRET_FIRE`／`THEME_AI`／`ELITE_AI`（`enemy_ai.js`）。資料表只寫「這個東西有」和它的數字（例：`WEAPONS[id].alt = { name, cd }`、`turret: { cd }`）。

### 同類東西：差別寫在資料，行為走繼承

- 只差數值 → 同一張表的不同列（`CHIPS`、`ENEMY_TYPES`、`PARTS`）。
- 行為不同 → **基底類別寫預設、子類別只覆寫不一樣的地方**。例：`WeaponPlay` 的每個方法預設 = 一般射擊；`ParkWeapon`（子彈會停在場上）多了 `shots`、`max`，飛輪、重力井繼承它；熱能光束、牽引鉤、能量刃、無人機直接繼承 `WeaponPlay`。Godot 對應 `class_name WeaponPlay` ＋ `extends`。
- 兩段程式一樣 → 抽成一個函式（例：重力井停住、黑洞彈飛行中都呼叫 `pullEnemies`）。
- 同一個數字在兩處算（遊戲判斷、HUD 顯示）→ 寫成方法、兩邊呼叫同一個（例：`Flywheel.max()`、`GrappleHook.holdT()`、`DroneSwarm.blockMax()`）。

### 層跟層怎麼溝通

- 邏輯 → 畫面：`Events.emit`（對應 Godot 的 signal）。多人連線要畫面做事：`Net.view(種類, 資料)` 發 `netView`，`ui/lobby.js` 的 `NetView` 照種類畫。
- 畫面 → 邏輯：呼叫方法（`Game.buy(i)`、`Range.setSpawn(type, lv)`、`Hub.setDriving(on)`）。畫面的狀態如果邏輯也要用，放在邏輯那邊（例：「基地的飛船能不能開」是 `Hub.driving`，不是 `Screen` 的欄位）。
- 存檔：`Save.load／save／remove／flag`（`system/save.js`），名稱都在 `Save.KEYS`。換 Godot／Steam 的存檔只改這一檔。

### 網頁版限定（換 Godot 時不用照搬）

| 網頁版 | Godot |
|---|---|
| 所有檔案共用全域範圍、載入順序寫在 `index.html` | 各自的 `class_name`／autoload |
| 一個大物件分檔：`Object.assign(Game, {…})` | 拆成幾個節點或 autoload |
| `effects.js` 的 `burst(x, y, 顏色…)`：邏輯帶顏色發特效事件 | 改成語意事件（「過熱」「擊沉」），顏色由畫面決定 |
| `localStorage`（只在 `save.js`） | `FileAccess`／Steam Cloud |

## 一幀（`core/main.js` 的 `frame`）

`Net.tick`（收送多人訊息）→ `Game.update`（戰鬥）→ `Hub.update`（基地）→ `Range.tick`（靶場）→ `render()`（WebGL 世界 `GLR`＋2D 畫布的 HUD）。每幀最多 1/30 秒；模擬（`tests/`）用固定 1/60 秒直接呼叫 `Game.update`，不經過 `frame`。

## 遊戲狀態（`Game.state`）

| 狀態 | 是什麼 | 畫面（`ui/listeners.js` 的 `VIEWS`） |
|---|---|---|
| `title` | 基地（單人） | `Screen.title` |
| `lobby`、`pick` | 多人：大廳、房間裡的基地 | `Net.renderLobby`、`Screen.hubPick` |
| `map` | 航圖 | `Screen.map` |
| `play` | 戰鬥（也是靶場） | 沒有 DOM；Esc 選單 `Screen.pauseMenu` |
| `reward`、`shop`、`workshop`、`armory`、`event` | 三選一、補給站、改裝廠、軍械台、？事件 | 同名的 `Screen.*` |
| `editor` | 電路編輯器（Tab）；關掉回到 `returnState` | `Editor` |
| `victory`、`dead`、`ended` | 打倒旗艦、陣亡、這一局結束 | 同名的 `Screen.*` |

換狀態後呼叫 `Game.view()`，它發 `view` 事件，`listeners.js` 照狀態畫對應的頁。

## 一局的流程

`Game.newRun` → `showMap`（航圖）→ `enterNode`（照節點種類進戰鬥或各種站）→ `startCombat` → `startWave`／`updateWaves` → `combatWon` → `openReward`（三選一）→ 回航圖 → 第 7 層旗艦 → `nextSector` → 最後一個星區打完 `finishRun` → `saveRecord`（遊玩紀錄＋解鎖進度）。

邏輯發、`ui/` 聽。完整清單用 `grep "Events.emit('"`。

| 類別 | 事件 | 誰聽 |

| 特效 | `burst`、`trail`、`floatText`、`ring`、`zap`、`flash`、`banner`、`shake`、`fxClear`、`fxTick` | `ui/fx.js`（發的一方用 `game/effects.js` 的小函式） |
| 音效 | `shoot`、`hit`、`dash`、`enemyShot`、`enemyKilled`、`playerHurt`、`explode`、`waveStart`、`bossArrive`、`chipTrigger`（晶片觸發）、`alt`（武器右鍵）… | `listeners.js` 的音效表 |

## 多人

- **座位**：每個玩家一份配裝 `L`（電路、倉庫、武器、數值…，欄位見 `game.js` 的 `LOADOUT_KEYS`）。單人 = 只有自己的房間：房主自己的是 `Game.L`、隊友的是 `mate.L`。`Game.chain`、`Game.wp` 這些欄位指向「目前在算的那個人」（`Game.cur`）；`Game.withLoadout(L, fn)` 只切換 `cur`（不抄欄位）。某艘船的配裝 `loadoutOf(p)`、武器玩法 `weaponPlay(p)`。
  - 跟著人走的事（子彈的停留／飛回、命中、擊殺、受傷、彈反、右鍵、能量刃排隊的刃片）都包在那個人的 `withLoadout` 裡跑，武器玩法程式只讀 `Game.wp`。
  - `owner`／`Game.shooter`：房主 = `null`、隊友 = 他的 `L`（`withLoadout(Game.L)` 時 shooter 也是 `null`）。
- **連線**：WebRTC 點對點（PeerJS 1.5.4）。PeerJS 的公開伺服器只負責配對；房號對應 Peer ID `circuitrogue-mp-XXXX`。`new Peer()` 沒傳設定，用 PeerJS 1.5.4 的預設 ICE（`peerjs.min.js` 的 `iceServers`）：Google STUN ＋ PeerJS 公開的中繼伺服器（TURN，`eu-0`／`us-0.turn.peerjs.com`）；直連打不通時改走 PeerJS 的 TURN（讀 code 推的，未實測）。TURN 是免費公共服務、不保證頻寬和穩定，所以少數網路還是可能連不上或延遲高；要穩就自己設 `iceServers`。
- **房主算整個戰場**：敵人、所有子彈、傷害、掉落、地圖物件、傳送門；替隊友開火（`Game.withLoadout` 暫時換上隊友的配裝）。每秒 30 次送戰場快照。
- **隊友算自己的移動和衝刺**（零延遲），每秒 30 次送位置、「有沒有按開火」、衝刺和右鍵的次數（`ds`、`as`：房主照次數執行）；房主把每個人的武器狀態（熱度、冷卻、無人機、鉤爪，`weaponRow`）放進快照；商店、獎勵等節點在自己電腦上處理，回航圖時把配裝傳給房主。
- **被拉的船自己拉自己**：拖曳艦的牽引（`Game.beamPull`，看敵人的 `tgt`）、牽引鉤勾隊友（`Game.shipPull`，看飛船的 `grabBy` = 勾住它的人的號碼，房主放進快照 `me`）都在被拉的那台電腦上拉，衝刺 = 掙脫。勾隊友被甩出去：房主送一次速度（`flingSeq`、`flingV`），隊友照「被彈開」（`kbT`）飛；倒下的船不會自己更新，房主拖（`Game.dragDowned`）、位置放進快照。
- **子彈只送隊友會猜錯的**：隊友那邊照直線自己飛；房主幫每個隊友記住上次送的直線，偏離超過 `BULLET_TOL`（轉彎、追蹤、飛回、停住）才重送，消失的只送編號（`Net.bulletRows`）。流量和誤差用 `tests/netsize.js` 量（`--build=late` 是後期配裝）。
- **隊友畫面上的敵人、子彈是同步來的資料**：畫面和兩邊共用的程式只讀欄位，不呼叫方法。
- **基地（房間）**：基地是一個房間的戰場（房間、開口的矩形做成場地 `Arena.fromRects`，標靶機是打不死的敵人 `dummy`）。**戰場那一套只寫一份**：每幀的邏輯是 `Game.step`（戰鬥的 `Game.update` 和基地的 `Hub.update` 都呼叫它），畫面是 `GLActors.draw`（敵人、預警線、飛船…），基地只有場地換成 `GLHub`（地板、牆、擺設）；戰場加新東西只改這兩處，基地自動有（機制檢查「基地跑戰場那一套」擋住基地另寫一份）。房間裡只同步位置和按鍵（開火、衝刺、右鍵次數）：每個人在自己這邊把別人的船跑一份（`Hub.updateGhosts`，放在 `Game.mates`），各自算；別人的子彈打到自己 → 自己的電腦把自己推開（`Hub.roomHits`，不扣血），別人的鉤爪打中自己 → 自己的電腦把自己拉過去（`GrappleHook.hookShips`，跟戰鬥同一套）。基地裡 `Game.mode = 'hub'`。
- **對方的資料一律不可信**：晶片 id、武器、零件層數、星圖、數值範圍都先檢查。
- 一則訊息超過 16KB（PeerJS 上限）會切段送；5 秒沒收到任何訊息算斷線（切到背景放寬到 70 秒）。
- 訊息種類：看 `net.js` 的 `onData` 裡的 `case`。
